# Reproducing *AddressSanitizer: A Fast Address Sanity Checker* (USENIX ATC 2012)

CS340 Operating Systems, Research Paper Replication, 2026–2027.

This repository reproduces the performance evaluation (Section 4) of
K. Serebryany, D. Bruening, A. Potapenko and D. Vyukov,
*AddressSanitizer: A Fast Address Sanity Checker*, USENIX ATC 2012
([paper](https://www.usenix.org/system/files/conference/atc12/atc12-final39.pdf),
[tool](https://clang.llvm.org/docs/AddressSanitizer.html)).
We test three claims:

| Claim | Paper | Where |
|---|---|---|
| C1 | ASan (reads+writes) slows SPEC CPU2006 by 73% on average, perlbench/xalancbmk most (2.60x/2.67x) | Figure 2, §4 |
| C2 | Instrumenting only writes reduces the average slowdown to 26% | Figure 2, §4 |
| C3 | Memory usage grows 3.37x (Table 1); stack grows noticeably for only a few programs (Table 2); binaries grow 1.5–3.2x | Tables 1–2, §4 |

Extension: effect of the minimum heap **redzone size** (16–256 B) on time and
memory (the paper claims in §4.3 that larger redzones slow down and inflate
programs that allocate many small chunks, but gives no data).

The report is in [`report/report.pdf`](report/report.pdf).

## Workloads (deviation from the paper)

SPEC CPU2006 is licensed and not available to us, so we use 11 open-source
programs. Seven are the same program as, or the same application domain as, a SPEC CPU2006
benchmark; two more (`tramp3d`, `lulesh`) are loose analogues:

| Ours | Version | SPEC CPU2006 counterpart | Input (generated by `scripts/gen_inputs.py`) |
|---|---|---|---|
| `perl` (miniperl) | 5.38.2 | 400.perlbench (same program) | text processing script over 6 MB of Perl sources |
| `bzip2` | 1.0.8 | 401.bzip2 (same program) | 24 MB mixed text/binary, `-9` compress + decompress |
| `gnugo` | 3.8 | 445.gobmk (same program) | GTP self-play, 13x13, 24 moves |
| `hmmer` | 3.4 | 456.hmmer (same program) | `hmmbuild` Pkinase + `hmmsearch --max` vs 8000 random proteins |
| `stockfish` | 16.1 | 458.sjeng (chess engine) | `bench 16 1 14` (depth 14, 1 thread) |
| `x264` | 31e19f92, `--disable-asm` | 464.h264ref (H.264 encoder) | 150 CIF frames, preset medium |
| `libxml2` (xmllint) | 2.12.9 | 483.xalancbmk (XML processing) | 40 MB XML: format + XPath |
| `tramp3d` | LLVM test-suite 18.1.8 | 447.dealII (C++ templates, FP) | `-n 100 --domain 40 40 40` |
| `lulesh` | 2.0.3 | 433.milc (FP physics) | `-s 30 -i 150` serial |
| `lua` | 5.4.6 | – (interpreter) | binary-trees, fannkuch, strings, spectral-norm |
| `sqlite` | 3.46.0 speedtest1 | – (database) | `--memdb --size 120` |

All sources are downloaded from upstream and verified by SHA-256
(`scripts/sources.txt`). Licenses: see [THIRD_PARTY.md](THIRD_PARTY.md).

## Requirements

* x86-64 Linux host with Docker (tested: Ubuntu 22.04 host, Docker 29.9).
* ~6 GB free disk, ≥ 6 GB RAM (ASan runs of libxml2 need ~1.5 GB).
* Network access for `make fetch` only.

Everything else (clang 18.1.3, Python, LaTeX) is pinned inside the Docker
image (`Dockerfile`, base image pinned by digest, compiler pinned by package
version). Running without Docker is possible with `NATIVE=1` if the host has
the same tools.

## Quick start

```bash
git clone https://github.com/CodeShiTianmin/AddressSanitizer.git && cd AddressSanitizer
make image      # build the pinned container                    (~3 min)
make fetch      # download + verify sources                      (~1 min)
make inputs     # generate deterministic inputs into data/      (~1 min)
make build      # 11 benchmarks x 4 build configurations         (~35 min on 2 cores)
make smoke      # optional: one run of every variant             (~3 min)
make run        # all experiments, results/raw/*                 (~2.5 h on 2 vCPUs)
make analyze    # tables (results/summary, report/generated) + figures (report/figures)
make report     # report/report.pdf
```

`make all` runs the whole pipeline. Individual experiments: `make main`,
`make controls`, `make redzone`, `make malloc-profile`, `make binsize`.
Runs are pinned to the last CPU (`BENCH_CPU` overrides). Re-running an
experiment **appends** further repetitions (numbered after the existing ones)
to its `runs.jsonl`; delete `results/raw/<exp>/` first for a clean run.

### Expected output

`make main` prints one line per run, e.g.

```
[run] rep1 bzip2      asan          wall=   5.104s hwm=    12.3MB rc=0
```

`make analyze` prints the key numbers (macros used in the report), e.g.
`OurAvgRW` (average slowdown, reads+writes) and `OurAvgWO` (writes only).
The values we obtained are in `results/summary/` and in the report.

## Layout

```
Dockerfile               pinned environment (ubuntu:24.04@sha256..., clang-18 1:18.1.3-1ubuntu1)
Makefile                 entry points (see above)
config/build_configs.sh  compiler flags: base / asan / asanwo / asanlean
config/experiments.json  experiment matrix: variants = (build, ASAN_OPTIONS), number of runs
scripts/                 fetch, input generation, build, run harness, environment capture
benchmarks/<name>/       build.sh (how to compile) and run.sh (the workload) per program
harness/procstat.c       LD_PRELOAD: records /proc/self/status Vm* fields at exit (paper's method)
harness/malloccount.c    LD_PRELOAD: counts heap allocations (base builds only)
analysis/                paper numbers (paper_data.py) and aggregation/plotting (analyze.py)
results/env.txt          machine, kernel, compiler of the recorded runs
results/raw/<exp>/       one JSON object per run (raw logs; every reported number derives from these)
results/summary/         CSV aggregates produced by analysis/analyze.py
report/                  LaTeX report; generated/ tables and macros, figures/
```

### Build configurations

| Name | Flags | Purpose |
|---|---|---|
| `base` | `-O2` | baseline, as in the paper (`clang -O2`) |
| `asan` | `-O2 -fsanitize=address` | C1, C3 |
| `asanwo` | `… -mllvm -asan-instrument-reads=false` | C2 (writes only) |
| `asanlean` | `… -fsanitize-address-use-after-return=never -fno-sanitize-address-use-after-scope` | control: without post-2012 instrumentation |

Run-time options (`ASAN_OPTIONS`), from §4 of the paper:
`redzone=32:malloc_context_size=0:quarantine_size_mb=0:detect_leaks=0:detect_stack_use_after_return=0`.

## Starting code and modifications

There is no artifact for the paper; the tool itself ships with LLVM. We use
the unmodified AddressSanitizer of **clang 18.1.3** (Ubuntu package
`1:18.1.3-1ubuntu1`, upstream tag `llvmorg-18.1.3`). No third-party file is
modified; projects are built with their own build systems and our flags.
Compatibility switches that are applied identically to every configuration:

* `gnugo`: `-fcommon -Wno-error=implicit-function-declaration -Wno-error=implicit-int -Wno-error=int-conversion` (2009 code vs. clang 18).
* `perl`: only `miniperl` is built (no dynamic loading), so `workload.pl` uses no modules.
* `stockfish`: `optimize=no` so that our `-O2` (not `-O3 -flto`) is used.
* `x264`: `--disable-asm --disable-thread`.

All files in this repository were written by the group (see the report's
contribution statement).
